# Decisions

This document holds the decisions that govern the workspace. A plan must not go
against a decision. To change a decision, propose the change and get human
approval first.

| ID   | Decision                                                                                                                                                    | Rationale                                                                                                                                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | The workspace and the library are separate public GitHub repositories, `FuguBSD/Workspace` and `FuguBSD/Wiki`.                                              | A remote buys the CI gates and the rulesets that a local repository cannot buy, and a public repository buys a ruleset on the Free plan of the org. The library must hold no secret, so the content rule of LIB-CONTENT applies to both.       |
| D-02 | Hooks fully replace the built-in worktree creation and removal of Claude Code.                                                                              | The built-in handling cannot bootstrap the gitignored trees that a worktree needs.                                                                                                                                                             |
| D-03 | A worktree bootstrap makes local clones from the main checkout, with no network and no `gh`.                                                                | A local clone is fast, works offline, and keeps parallel agents independent of the network.                                                                                                                                                    |
| D-04 | The workspace consumes the `org` and the `infra` packs of FuguBSD/Tooling, and is organized as the other consumers are.                                     | One toolchain and one layout serve every repository, and the drift stays visible through the sync script.                                                                                                                                      |
| D-05 | `worktree.pl envsync` merges each `.env` of a checkout into the `env` block of `.claude/settings.local.json`, and the shallowest file wins a contested key. | The block reaches every Bash call, so a bare allow-listed command gets the workspace-root credentials. The merge widens exposure across the projects of one local machine, and the shadow warning names each key that needs explicit sourcing. |
| D-06 | A worktree is never removed automatically. An operator removes a worktree by hand.                                                                          | A session captures its work in the clones inside its worktree. An automatic removal at a failed or an abandoned session destroys that work. The accepted cost is a worktree that accumulates, and `worktree.pl list` is the mitigation.        |
| D-07 | The library is a git repository at `Wiki/`, and each checkout clones it, as each checkout clones `Projects/`.                                               | One clone per checkout keeps two parallel sessions off one git index. The clones contend on `origin` only, and a fetch-rebase-retry settles that race.                                                                                         |
| D-08 | The agent files and the skills of the observer set live in this workspace checkout only. No Tooling pack carries them.                                      | The set operates three projects from outside them, so it belongs to the workspace. A pack would copy it into each consumer, where it has no target to operate.                                                                                 |
| D-09 | The library is the working record, and a project ledger receives one batch per campaign.                                                                    | Capture must stay cheap and must survive a crash, so an observation goes to a git commit at once. Review cost belongs on the batch, not on each entry.                                                                                         |
